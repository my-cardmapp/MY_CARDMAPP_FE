Card-Map 프로젝트 요구사항 정의서 (PRD)

1. 프로젝트 개요
   제품명: Card-Map (카드맵) - 복지카드 가맹점 통합 검색 플랫폼
   비전: 모든 복지카드 사용자가 쉽게 가맹점을 찾고, 최적의 경로를 계획할 수 있는 원스톱 플랫폼
   
   목표 사용자:
   - 주 타겟: 아동급식카드 사용 청소년 (13-18세)
   - 부 타겟: 문화누리카드, 지역사랑상품권 사용자
   - 확장 타겟: 복지카드 발급 가족, 사회복지사

2. 핵심 기능 요구사항

   Phase 1 - Core Features (2개월):
   - 지도 기반 가맹점 표시
     * 현재 위치 기반 주변 가맹점 표시
     * 카드별 필터링 (문화누리, 아동급식, 지역사랑상품권)
     * 카테고리별 필터링 (음식점, 마트, 서점 등)
     * 가맹점 상세 정보 표시
   
   - 기본 검색 기능
     * 가맹점명 검색
     * 주소 기반 검색
     * 검색 결과 정렬 (거리순, 인기순)
   
   - 데이터 수집 및 처리
     * 공공데이터 API 연동 (문화누리, 아동급식, 지역사랑상품권)
     * Kakao Local API를 통한 데이터 보강

   Phase 2 - Route Planning (1개월):
   - 경로 탐색
     * 단일 목적지 경로 안내
     * 다중 경유지 경로 최적화 (최대 5개)
     * 대중교통/도보 경로 지원
   
   - 경로 관리
     * 경로 저장 및 공유 기능
     * 자주 가는 경로 즐겨찾기

   Phase 3 - AI Integration (1.5개월):
   - 자연어 검색
     * LangChain4j 기반 의도 분석
     * 대화형 검색 인터페이스
   
   - 음성 검색
     * Web Speech API 활용
     * 음성 명령 지원
   
   - 개인화 추천
     * 사용자 검색 패턴 분석
     * 시간대별 맞춤 추천

   Phase 4 - User Features (1개월):
   - 사용자 계정
     * 소셜 로그인 (카카오, 네이버)
     * 프로필 및 카드 정보 관리
   
   - 가맹점 평가
     * 별점 및 리뷰 작성
     * 사진 업로드
   
   - 오프라인 지원
     * PWA 구현
     * 오프라인 지도 캐싱

3. 기술 요구사항
   
   백엔드:
   - Spring Boot 3.2 + Java 21 (Virtual Threads)
   - PostgreSQL 16 + PostGIS 3.5
   - Redis 7 (캐싱)
   - LangChain4j + OpenAI API
   
   프론트엔드:
   - Next.js 14 (App Router) + TypeScript
   - Tailwind CSS + Shadcn/ui
   - Naver Map SDK
   - React Query (데이터 페칭)
   
   인프라:
   - Docker + Docker Compose
   - GitHub Actions (CI/CD)
   
   성능 요구사항:
   - 검색 응답시간: p95 < 300ms
   - 경로 계산: p95 < 500ms
   - AI 응답: p95 < 2s
   - 동시 사용자: 10,000+ 지원

4. 데이터 처리 전략
   
   데이터 소스:
   - 문화누리카드 가맹점 데이터 (약 200,000개)
   - 아동급식카드 가맹점 데이터 (약 150,000개)
   - 지역사랑상품권 가맹점 데이터 (약 500,000개)
   
   데이터 보강:
   - Kakao Local API 활용 (일일 10만건 무료)
   - 하이브리드 처리: 배치 처리 + 실시간 조회
   - 우선순위 기반: 인기 지역/가맹점 우선 처리
   - 점진적 품질 개선: 사용자 피드백 활용
